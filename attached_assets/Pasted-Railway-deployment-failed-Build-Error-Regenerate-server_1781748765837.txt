## Problem
The build fails during `npm install --prefix server --omit=dev` with `ENOTFOUND package-firewall.replit.local`. The `server/package-lock.json` contains `resolved` URLs pointing to Replit's internal npm registry proxy, which is only accessible within Replit's infrastructure.

## Diagnosis
The project was developed on Replit, which routes npm traffic through an internal proxy (`package-firewall.replit.local`). When npm generates or updates `package-lock.json` on Replit, it records this internal proxy URL in the `resolved` field for each package. When Railway's builder runs `npm install --prefix server`, it reads these URLs from the lockfile and attempts to download packages from the unreachable Replit proxy, causing DNS resolution failures.

Affected packages in `server/package-lock.json`:
- `@otplib/core@12.0.1` — resolved: `http://package-firewall.replit.local/npm/@otplib/core/-/core-12.0.1.tgz`
- `@otplib/plugin-crypto@12.0.1` — resolved: `http://package-firewall.replit.local/npm/@otplib/plugin-crypto/-/plugin-crypto-12.0.1.tgz`
- `@otplib/plugin-thirty-two@12.0.1` — resolved: `http://package-firewall.replit.local/npm/@otplib/plugin-thirty-two/-/plugin-thirty-two-12.0.1.tgz`
- `@otplib/preset-default@12.0.1` — resolved: `http://package-firewall.replit.local/npm/@otplib/preset-default/-/preset-default-12.0.1.tgz`
- `@otplib/preset-v11@12.0.1` — resolved: `http://package-firewall.replit.local/npm/@otplib/preset-v11/-/preset-v11-12.0.1.tgz`
- `thirty-two@1.0.2` (transitive dependency of @otplib/plugin-thirty-two)

## Fix
1. File: `server/package-lock.json`
2. This file cannot be safely edited by hand — it must be regenerated by npm to ensure consistency of integrity hashes and dependency resolution.
3. Steps:
   - Delete `server/package-lock.json` from the repository.
   - From a non-Replit environment (local machine, GitHub Codespace, or CI pipeline), run `cd server && npm install`.
   - Commit the regenerated `server/package-lock.json`.
4. The regenerated lockfile will have all `resolved` URLs pointing to `https://registry.npmjs.org/`, which is accessible from Railway's build infrastructure.
